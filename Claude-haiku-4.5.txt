## Summary of Changes

### Problem
When SQLMesh rendered a SEED (CSV) model with quoted column names in the Postgres dialect (e.g., `"camelCaseId"`), the CSV header columns were being normalized to lowercase. This caused a `KeyError` when `render_seed()` tried to access columns using the case-sensitive keys from `columns_to_types_`.

### Solution
I implemented a three-part fix:

#### 1. **seed.py** - Enhanced CsvSeedReader
- Added `set_expected_columns()` method to accept a mapping of CSV column names to expected model column names
- Modified `_get_df()` to use the provided mapping instead of always normalizing columns
- This allows intelligent matching between CSV headers and model column definitions

#### 2. **definition.py** - Enhanced SeedModel  
- Added imports for `csv`, `io`, and `normalize_identifiers`
- Created `_setup_reader_column_mapping()` method that:
  - Reads the CSV headers in their raw form
  - For each CSV header, tries to match it to model columns with intelligent logic:
    - First checks for exact case-sensitive matches (for quoted columns like `"camelCaseId"`)
    - Then tries normalized matches (for unquoted columns that follow dialect rules)
  - Passes the mapping to the reader before rendering
- Modified `render_seed()` to call the mapping setup before reading data

#### 3. **seed_models.md** - Updated Documentation
Added a new "Column name case sensitivity" section documenting:
- How Postgres handles quoted vs unquoted column names
- The difference between case-sensitive (quoted) and case-insensitive (unquoted) columns
- Practical examples showing how CSV headers should match model definitions
- Compatibility considerations for existing projects

### Behavior Changes

**For quoted column names** (e.g., `"camelCaseId"`):
- Before: CSV headers were normalized to lowercase, causing mismatches
- After: Quoted columns must match the CSV header exactly, preserving case

**For unquoted column names** (e.g., `category`, `PRICE`):
- Before: Normalized to lowercase
- After: Normalized to lowercase (unchanged - maintains backward compatibility)

All existing tests pass, including the three comprehensive test cases in test_seed_case_sensitivity.py:
- ✅ `test_seed_case_sensitive_columns_postgres` - Quoted camelCase columns
- ✅ `test_seed_case_sensitive_partial_columns` - Mixed quoted and unquoted columns  
- ✅ `test_seed_case_sensitive_mixed_quotes` - Various case combinations

The fix properly handles the Postgres dialect's case-sensitive identifier rules while maintaining backward compatibility with existing unquoted column definitions.
